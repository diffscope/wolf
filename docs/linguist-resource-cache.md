# wolf 语言域资源缓存（正交面）

本文规定推理资源在进程内的共享机制。

**资源缓存是架构必需件，不是优化。** 依据是并发模型（架构文档 A14）：`srt::InferenceExecutive`
是单任务面，因此 k 路并发对应 k 棵执行体子树，即 k 组 G2P / S2P / Onset 执行体。**若执行体之间
不共享资源，k 路并发即加载 k 份词典。**

> **更正（A59）**：本段原写「k 份词典**与 k 组模型会话**」，后半句**对 ONNX 不成立**。ONNX 驱动
> 已按 `path` 与 `(size, hash)` 两级索引、以引用计数持有 `SessionImage`（内含 `Ort::Session`），
> 同一模型文件被 N 个 `InferenceSession` 打开时**权重只加载一份**
> （`dsinfer/plugins/inferencedrivers/onnxdriver/Session/SessionSystem.h:20-46`、
> `Session/Session.cpp:523-660`）。因此本文的适用范围是**解析产物**，不含模型权重；模型权重由
> 驱动层自行去重，与 §1「明确不缓存的对象」划定的边界一致。

上位规范为 [spec 2.4](ds-spec-2.4.md)；分层见 [linguist-architecture.md](linguist-architecture.md)。
本文属于 wolf 的实现文档，不是对外契约。

**透明性要求**：缓存不改变 `exports`、`configuration` 与运行时 IO 的任何可观察行为。缓存内容、
键的组成与命中率均不进入声明面，**包作者无须感知缓存，也不承担新义务**。

## 1. 缓存对象

**缓存对象为解析产物**：词典表、音素集、词表结构、Onset 规则集等在加载期一次性构造的**只读**
内存结构。原始字节不缓存，因为没有消费方。

**明确不缓存的对象**：

- **模型会话与推理驱动句柄**：线程亲和性与会话状态属于驱动层。**ONNX 驱动已按内容自行去重**
  （见上方更正），本层不介入；
- **逐词查询或推理结果**：属于记忆化，与本文的资源去重是不同的层次；
- **Lua 脚本执行体**：其安全边界由沙箱约定规定；
- **cpp-pinyin 引擎实例**：其转换方法声明为 `const`，却修改实例内部的暂存状态（决策 A32 / B1-b），
  不是只读产物，放入缓存会破坏本文 §1 的不变式。每个后端执行体各持有一个实例。

### 1.1 硬约束：解析产物不依赖基路径

> 解析产物**不得**记录来源目录或解析期的绝对路径。资源内的相对引用保持相对形式，基路径由
> 消费方在使用处提供。

该约束是内容寻址共享的**正确性前提**：若解析产物在解析时展开了来源路径，两个包共享同一内容的
条目时，后加载的包会静默使用先加载的包的目录。违反本约束的变体解析产物**不得进入内容寻址缓存**。

## 2. 键

```
cacheKey = { contentHash, resourceKind, parserFingerprint }
```

| 分量 | 含义 |
| :-- | :-- |
| `contentHash` | 文件全部字节的强散列，采用 BLAKE3。要求：确定性、足够的抗碰撞性、可流式计算 |
| `resourceKind` | 变体内部的资源类型名（如 `s2p-dict-tsv`、`onset-rule-json`）。**同一物理文件由不同族的解析器解析时属于不同的 kind，不共享条目** |
| `parserFingerprint` | 变体名与资源格式世代（`formatVersion` 等原生版本字段；无原生版本字段的资源族使用按 kind 声明的语法世代常量，如 `s2p-dict-tsv@1`）。实现中对应 `ResourceCache::acquire` 的 `parserGeneration` 参数 |

格式演进后，`parserFingerprint` 的变化使旧条目不再命中，**无须显式失效**。

> 解析器的实现修订不进入键：缓存只在进程内有效，插件随 Runtime 常驻且不可替换
> （spec 2.4:584-586），因此同一进程内不会同时存在两个修订版本。若将来需要跨进程持久化，须先
> 确定版本的取值来源；现行插件元数据没有版本字段（`plugin.json` 只有根级 `name` 与 `interpreters`）。

### 2.1 路径快路径

provider 域另持有记忆表 `canonicalPath → (size, mtime, contentHash)`：

- 同一路径再次加载时，先读取文件的 `(size, mtime)` 并查该表，吻合时**不再读取文件内容**，直接以
  记录的散列查缓存；
- 不吻合或无记录时才读取文件并流式计算散列。读取文件本来是解析的必要 IO，散列计算叠加在同一次
  读取上，未命中时的额外成本近似为零。

**信任边界**：「同一身份的 Package 在使用期间内容不变」由包作者与部署方保证（与 spec 2.4:382
同源的豁免口径）。因此，保持尺寸与时间戳不变的原地改写会被视为未变化并沿用既有条目；该场景违反
上述保证，**缓存不负责检测**。

## 3. 归属与生命周期

- **归属于 provider 执行域**：spec 2.4:440-442 允许 provider 级基础设施不归属于任何 Package，
  :586 规定插件常驻至 Runtime 销毁。缓存表位于推理 provider 一侧，Package 卸载只减少引用计数；
- **解析产物由缓存重新持有**（实现约束，不是可选优化）：:586 规定的常驻以 **Runtime 为界**，
  而缓存存续到进程结束，因此缓存**比生成其条目的插件存续得更久**。`std::shared_ptr` 的控制块
  及其析构代码由分配它的插件生成；若缓存直接以弱引用指向该控制块，最后一个弱引用的释放会执行
  已卸载的代码，**进程退出时必然崩溃**。因此 `acquire` 把插件交回的产物重新包装进一个由本库生成
  控制块的 `shared_ptr`：删除器在**强引用计数归零时**（插件仍已加载）释放插件持有的那份引用，此后
  控制块只剩空状态，退出时销毁它是安全的。弱引用始终指向本库的控制块；
- **释放**：引用计数归零即析构；缓存表持有弱引用，不延长条目的生存期；
- **线程安全**：读写锁（共享读、独占写）；同一键的并发解析请求经在飞表合并，同一资源不会被并发
  重复解析；
- **在飞解析的结束处理**：同一键的并发请求等待首个解析的结果。解析以任何方式结束（返回值、返回
  错误或抛出异常）时，都将该键移出在飞表，并把结果交给全部等待者。抛出异常时，解析线程照常收到
  异常，等待者收到一个带资源路径的 `InvalidFormat` 错误，此后对同一资源的请求重新解析；
- **回收失效条目**：弱引用已失效的条目按插入次数回收，每 256 次插入扫描一次，而不是在表长达到
  阈值后每次插入都扫描；
- **失效**：内容寻址本身不存在失效问题，检测到的内容变化即对应新的键。记忆表条目在 `(size, mtime)`
  不吻合时惰性过期；
- **容量**：Level 1 不设上限（解析产物为文本表结构，体量可控）。引入大矩阵类资源时再评估
  LRU 与容量上限。

## 4. 与加载事务的关系

- 注入点位于推理 provider 的 **Acquire** 资源装配内部（spec 2.4:425：Acquire 取得尚未激活的
  运行时资源）。缓存命中表示取得同一资源对象，而不是重复取得资源；
- **rollback 的撤销等价性**：条目的引用计数随持有它的模块对象析构而归零。synthrt 的 rollback 由
  析构驱动（未 Commit 的实例不经过 quit/wait：`synthrt/lib/Core/PackageHandle.cpp:17-20` 在未
  loaded 时提前返回），对象所有权即 spec 2.4:446 完成日志的等效记录，析构顺序即其逆序撤销（:456）。
  其他持有者已引用的条目在本事务 rollback 后仍保留，这是合法的（计数只减去本事务的那一份，:460）；
- **与覆写语义兼容**：声库逐项覆写等价于在不同包路径下复制资源。内容相同时内容键命中并共享，内容
  不同时键不同、各自加载；两种情况的可观察行为与无缓存时逐字节一致。

## 5. 验收基线

- 加载同一语言包两次，或两个语言共享同一后端资源时，**同一路径**资源的读盘与解析次数由 N 降为 1；
- **不同路径、相同内容**时，解析次数降为 1（读盘次数不少于路径数，这是物理下限：内容未知前无法
  免去读取）；
- 单元测试：两个并发执行体对同一资源的读盘次数为 1；散列碰撞注入；记忆表 `(size, mtime)` 不吻合
  时重新读取；**反复创建与销毁 SynthUnit（每次都卸载插件）后进程正常退出**，这一条是 §3 控制块
  归属规则的可执行表述；
- 全部既有单元测试与对照运行的输出**逐字节一致**（透明性要求的可执行表述）。
