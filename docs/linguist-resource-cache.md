# wolf 语言域资源缓存（正交面）

本文钉推理资源的进程内共享机制。

**它不是优化，是架构必需件。** 依据是并发模型（架构文档 A14）：`srt::InferenceExecutive`
是单任务面，故并发 k 路 = k 棵执行体子树 = k 组 G2P / S2P / Onset 执行体。**没有跨执行体的
资源共享，k 路并发就是 k 份词典。**

> **更正（A59）**：本段原写「k 份词典**与 k 组模型会话**」，后半句**对 ONNX 不成立**。ONNX 驱动
> 已按 `path` 与 `(size, hash)` 两级索引、引用计数持有 `SessionImage`（内含 `Ort::Session`），
> 同一模型文件被 N 个 `InferenceSession` 打开**权重只载一份**
> （`dsinfer/plugins/inferencedrivers/onnxdriver/Session/SessionSystem.h:20-46`、
> `Session/Session.cpp:523-660`）。本文的适用面因此是**解析产物**，不含模型权重——后者由驱动
> 层自行去重，正如 §1「明确不缓存」所划的界。

上位规范 [spec 2.4](ds-spec-2.4.md)；分层见 [linguist-architecture.md](linguist-architecture.md)。
本文属 wolf 实现文档，不是对外契约。

**透明性底线**：缓存不改变任何 `exports` / `configuration` / 运行时 IO 的可观察行为。内容、
键汇、命中率均不进入声明面，**包作者无感知、无新义务**。

## 1. 缓存什么

**缓存对象 = 解析产物**：词典表、音素集、词表结构、Onset 规则集等加载期一次性构造的**只读**
内存结构。不缓存原始字节（无消费方）。

**明确不缓存**：

- **模型会话与推理驱动句柄**——线程亲和与会话状态属 driver 面。**ONNX 驱动已自行按内容去重**
  （见上方更正），故本层不必也不应插手；
- **逐词查询/推理结果**——属另一层（记忆化），与本文的资源去重不是一回事；
- **Lua 脚本执行体**——安全边界遵循沙箱约定；
- **cpp-pinyin 引擎实例**——其转换方法为 `const` 却改写实例暂存（决策 A32 / B1-b），不是只读
  产物，进缓存即破坏本文 §1 的不变式。每个后端执行体各持一个实例。

### 1.1 硬约束：解析产物必须基路径纯净

> 解析产物**不得**捕获来源目录或解析期绝对路径。资源内的相对引用保持相对形态，基路径由
> 消费方在用点自带。

这是内容寻址共享的**正确性前提**：若产物 eager-resolve 了来源路径，两个包共享同内容条目时会
静默串到先载者的目录。违反本约束的变体解析产物**不得进入内容寻址缓存**。

## 2. 键

```
cacheKey = { contentHash, resourceKind, parserFingerprint }
```

| 分量 | 含义 |
| :-- | :-- |
| `contentHash` | 文件全字节的强散列。要求：确定性、抗碰撞足够、流式可算、不引额外依赖 |
| `resourceKind` | 变体内部的资源类型名（如 `s2p-dict-tsv`、`onset-rule-json`）。**同一物理文件被不同族解析器解析是不同的 kind，绝不共享** |
| `parserFingerprint` | 变体名 + 资源格式世代（`formatVersion` 等原生版本字段；无原生版本字段的资源族以按 kind 声明的语法世代常量填充，如 `s2p-dict-tsv@1`） |

`parserFingerprint` 使格式演进后旧条目自然不再命中，**无需显式失效**。

> 解析器实现修订不入键：进程内缓存 × 插件随 Runtime 常驻不可换（spec 2.4:584-586）⇒ 同一
> 进程内不可能出现两个修订版并存。跨进程持久化若将来需要，须先解决版本取值来源——现行插件
> 元数据无版本字段（`plugin.json` 仅根级 `name` + `interpreters`）。

### 2.1 路径快路径

provider 域另持记忆表 `canonicalPath → (size, mtime, contentHash)`：

- 同一路径再加载时先查该表，`(size, mtime)` 吻合即**免重读盘**，直接取 hash 查缓存；
- 失配或缺席才读盘并流式算 hash。读盘本就是解析的必要 IO，hash 叠加其上，miss 场景的额外
  成本 ≈ 0。

**信任边界**：「同身份 Package 的内容在使用期间稳定」是包作者与部署方的承诺（与 spec 2.4:382
同源的豁免口径）。因此「同尺寸且同时间戳的原地改写」会被视为未变化并沿用既有条目——该场景
违反上述承诺，**缓存不为其检测负责**。

## 3. 归属与生命周期

- **归属 provider 执行域**：spec 2.4:440-442 允许 provider 级基础设施不归属于任一 Package，
  :586 规定插件常驻至 Runtime 销毁。缓存表挂在推理 provider 侧，Package 卸载只减少引用计数；
- **解析产物由缓存侧重新持有**（实现约束，非可选优化）：:586 的「常驻」以 **Runtime 为界**，
  而缓存活到进程结束，所以缓存**比生成它条目的插件活得久**。`std::shared_ptr` 的控制块连同
  其析构代码由分配它的插件产出，若缓存直接弱引用该控制块，最后一个弱引用的释放就落在已经
  unmap 的代码上——**退出期必崩**。因此 `acquire` 把插件交回的产物重新包进一个由本库生成控制块
  的 `shared_ptr`：删除器在**强引用归零时**（插件尚在）丢掉插件那份引用，此后控制块只剩空状态，
  退出期销毁它是安全的。留给弱引用的，永远是本库自己的控制块；
- **释放**：引用计数耗尽即析构；缓存表持弱引用，不延缓条目死亡；
- **线程安全**：读写锁（共享读、独占写）；解析-插入在锁内原子完成（或 double-checked），
  防止并发重复解析同一资源；
- **失效**：内容寻址天然无失效问题——被检测到的变内容即变键。记忆表条目在 `(size, mtime)`
  失配时惰性过期；
- **容量**：Level 1 不设上限（解析产物为文本表结构，体量可控）。引入大矩阵类资源时再评
  LRU + 上限。

## 4. 与加载事务的关系

- 注入点在推理 provider 的 **Acquire** 资源装配内部（spec 2.4:425：Acquire 取得尚未激活的
  运行时资源）。缓存命中只是「取得同一资源对象」，而非「重复取得」；
- **rollback 撤销等价性**：条目引用计数随持有它的模块对象析构归零。synthrt 的 rollback 是
  析构驱动的（未 Commit 实例不经 quit/wait：`synthrt/lib/Core/PackageHandle.cpp:17-20` 未
  loaded 即早退），对象所有权即 spec 2.4:446 完成日志的等效记录，析构序即其反序撤销（:456）。
  他人已持引用的条目在本事务 rollback 后留存属合法（计数只减本事务那一份，:460）；
- **覆写语义兼容**：声库逐项覆写 = 不同包路径下的资源复制。同内容则内容键命中共享，不同内容
  则键不同各载各的——两种情况的可观察行为与无缓存时逐字节一致。

## 5. 验收基线

- 加载同一语言包两次 / 两个语言共享同一后端资源时，**同一路径**的资源读盘与解析次数由 N 降为 1；
- **异路径同内容**时解析次数降为 1（读盘次数不少于路径数是物理下限——不知内容前无法免读）；
- 单测：并发双执行体对同一资源的读盘次数断言 = 1；hash 碰撞注入；记忆表 `(size, mtime)`
  失配重读；**反复建销 SynthUnit（每次都卸载插件）后进程正常退出**——这条是上一节控制块归属的
  可执行表述；
- 全部既有单测与对照运行输出**逐字节一致**（透明性底线的可执行表述）。
